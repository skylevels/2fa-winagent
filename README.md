# Windows domain authorization agent

Исходники: [skylevels/2fa-winagent](https://github.com/skylevels/2fa-winagent). При установке из клона репозитория зависимости устанавливаются командой `composer install --no-dev --prefer-dist --no-interaction`; затем выполняются шаги подготовки Windows ниже. Автоматический установщик скачивает уже подготовленные зависимости.

Открытый PHP + PowerShell агент для Windows Server 2022. Он принимает подписанные HTTPS-команды от сервера мобильной авторизации и меняет `userWorkstations` пользователя на **локальном контроллере домена**. На контроллерах `dosifey.elemer.org` и `pimen.elemer.org` запускаются отдельные экземпляры; порядок новых выдач задаётся настройками портала.

Отдельный режим техподдержки снимает ограничение по рабочим станциям на настроенный срок 30–180 секунд, по умолчанию 60, в пределах существующих прав AD/Windows. Его endpoints, capability `support_all_v1`, исключения и ограничения при сбоях описаны в [support API](docs/support-api.md). Обычные пары логин/ПК используют настроенный срок 30–600 секунд, по умолчанию 300; одновременно смешивать режимы для одного пользователя нельзя.

Агент не завершает открытые сеансы Windows/RDP. Настроенный срок — окно для новых входов. Совместимость ограничений с конкретными способами входа и разблокировки проверяется отдельно на Windows 10/11: [план проверки](docs/WINDOWS-VALIDATION.md).

## Правила

| Операция | Изменение AD | Таймеры этого экземпляра |
|---|---|---|
| Разрешить `ivanov-dd` → `IVANOV-2121` | Добавить компьютер к текущему списку | Создать/продлить срок пары в пределах grantDurationSeconds |
| Повторить тот же запрос с тем же `request_id` | Вернуть `already_processed`, исходный результат и текущее наличие локального таймера | Не продлевать срок |
| Новое разрешение той же пары | Компьютер остаётся в списке | Обновить срок новым запросом |
| Истечение любого разрешения пользователя | Заменить **весь** список заглушкой | Отменить остальные локальные разрешения этого пользователя |
| Досрочно отозвать пару | Удалить только указанный компьютер; добавить заглушку, если её нет | Отменить таймер этой пары |
| Массово включить второй фактор | Добавить заглушку, сохранив остальные компьютеры | Разрешить обработку новых выдач |
| Массово выключить второй фактор | Полностью очистить атрибут | Отключить выдачи и отменить все локальные таймеры |

Заглушка по умолчанию — `2FA-BLOCK`. Реального компьютера с этим именем в AD быть не должно. Добавление заглушки **не запрещает** компьютеры, уже присутствующие в списке. Пустой атрибут означает отсутствие ограничений по рабочим станциям, поэтому массовое выключение снимает ограничения. [Описание Microsoft](https://learn.microsoft.com/en-us/windows/win32/ad/security-properties).

Участники `2fabypass` вообще не изменяются. Для этой группы учитывается прямое членство, в том числе назначение её основной группой; вложенные группы не раскрываются. Даже ранее установленная заглушка у такого пользователя остаётся без изменений.

Во всех операциях исключаются встроенный доменный Administrator по RID 500, Domain Admins, Enterprise Admins и BUILTIN Administrators. Для административных групп учитывается вложенное и основное членство; переименование группы или встроенного администратора не отменяет исключение. Ошибка определения исключений препятствует изменению пользователя.

## Порядок отправки команд

Новую выдачу мобильный портал начинает с первого настроенного агента и при неудаче переходит к следующему. До команды выполняется подписанный трёхсекундный `/v1/status`; бюджет самой AD-команды отдельный, по умолчанию 130 секунд. Портал сохраняет каждого получателя непосредственно перед отправкой: потерянный ответ не доказывает, что запись AD не выполнялась.

При переходе к следующему агенту сохраняются исходные тело, `request_id`, `sequence` и `expires_at`; timestamp/nonce и подпись создаются заново для получателя. Продление обычной пары и отзыв закреплены за всеми записанными получателями исходной выдачи и не переадресовываются другому DC. Портал считает очистку законченной только после подтверждения всех возможных получателей. Для поддержки вместо продления требуется новое подтверждение SMS на портале.

Агенты не связываются между собой, не выбирают роли и не переносят таймеры. Каждый изменяет AD на своём контроллере и выполняет только свои таймеры. Репликацию атрибута `userWorkstations` выполняет AD. [Модель репликации Microsoft](https://learn.microsoft.com/en-us/windows/win32/ad/a-programmerampaposs-model-of-replication-in-active-directory-domain-services).

При аварии процесса локальный таймер теряется. Портал сохраняет сроки и адресатов; ручные отзывы по кнопке повторяет до исходного дедлайна, но при недоступности DC своевременная запись запрета не гарантируется. Репликация AD не даёт атомарного общего порядка между узлами. Открытые сеансы Windows/RDP продолжаются независимо от удаления разрешения.

## Длительность доступа

В `C:\2fa\agent\config.json`: `grantDurationSeconds` — 30–600 целых секунд, по умолчанию 300; `supportDurationSeconds` — 30–180, по умолчанию 60. Значения одинаковы у всех участвующих агентов. Подписанный статус публикует `grant_duration_seconds`/`support_duration_seconds`, портал использует их при первой отправке. После ручного изменения конфигурации требуется перезапуск; сначала завершить текущие окна и очистку, поскольку состояние таймеров остаётся только в RAM. Пошаговые команды — в [инструкции администратора](docs/instruction.txt).

## Состояние только в памяти

Таймеры, результаты повторных команд, использованные nonce и текущий режим не записываются на диск. Успешные результаты команд хранятся в ограниченном кэше десять минут; актуальный неудавшийся отзыв сохраняется до успешного повтора или смены последнего номера; максимальный принятый `sequence` каждого пользователя — до перезапуска. После перезапуска:

- таймеры и история команд потеряны, а записанные в AD разрешения остаются;
- режим берётся из `startEnabled` в конфигурации;
- прежние таймеры не восстанавливаются и не передаются другому агенту; новые команды поступают по обычному приоритету Dosifey → Pimen;
- прежний запрос может снова попасть в обработку, поскольку долговременного журнала нет;
- без работающего агента и доступного AD срок отзыва гарантировать нельзя.

Конфигурация, код и журналы Windows существуют на диске; запрет хранения состояния относится к состоянию разрешений. В программе нет фоновой резервной службы отзыва или постоянной базы таймеров.

## Установка с загрузкой компонентов

Для новой установки скачайте [Install-AgentOnline.ps1](https://raw.githubusercontent.com/skylevels/2fa-winagent/main/deploy/Install-AgentOnline.ps1) и запустите в 64-битной Windows PowerShell от имени администратора на нужном DC:

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$installerPath = Join-Path $env:TEMP 'Install-AgentOnline.ps1'
Invoke-WebRequest -UseBasicParsing -TimeoutSec 120 -Uri 'https://raw.githubusercontent.com/skylevels/2fa-winagent/main/deploy/Install-AgentOnline.ps1' -OutFile $installerPath
& $installerPath -CAHost 'dosifey.elemer.org'
```

Скрипт спросит фактический IP мобильного сервера. Можно передать его сразу: `-AllowedIP '192.0.2.10'` со своим IP. Шаблон по умолчанию — существующий `WebServer10y`. Для явного выбора CA добавить `-CAConfig 'dosifey.elemer.org\<имя-CA>'`.

Установщик скачивает исходники с PHP-зависимостями из одного коммита GitHub, официальный PHP 8.4.27-1 NTS x64 и VC++ Runtime Microsoft. Проверяет SHA-256 исходного ZIP/PHP и подпись Microsoft у VC++, включает OpenSSL, получает сертификат, вызывает локальный установщик и запускает задачу агента. Папки защищаются до записи. Исходники с зависимостями публикуются в `dist/windows-agent.zip`; собственных скомпилированных EXE/DLL агента нет.

Установка в `C:\2fa`: код `agent`, PHP `php`, документы `docs`, журналы `logs`, переносимый комплект `distrib`. Нужны интернет к GitHub/PHP/Microsoft, модуль ActiveDirectory и настроенный Enterprise CA/шаблон на десять лет. Сервер должен быть записываемым DC. Существующие файлы агента/PHP и зарегистрированные задачи не перезаписываются.

Если VC++ требует перезагрузку, скрипт завершится до размещения и запуска агента: перезагрузите сервер и повторите. Если CA оставил запрос на согласовании, файлы сохраняются; после одобрения выполните `deploy\Request-AgentCertificate.ps1 -RequestId <ID> -PhpPath 'C:\2fa\php\php.exe'`, затем `deploy\Install-Agent.ps1 -PhpPath 'C:\2fa\php\php.exe'` и запуск задачи. Если задачи уже зарегистрированы, следуйте сообщению об ошибке и инструкциям восстановления.

После установки перенесите созданный `apiSecretHex` в нужный слот портала. Если группы `2fabypass` ещё нет, создайте её один раз локальной командой ниже и дождитесь репликации. Массовое включение второго фактора остаётся отдельной командой администратора.

## Подготовка Windows

Требуются PHP CLI 8.2+ x64 с расширением `openssl`, Composer для сборки зависимостей, Windows PowerShell 5.1, модуль ActiveDirectory и права записи `userWorkstations` у обслуживаемых пользователей. PHP запускается как постоянный процесс, без IIS и без `php -S`. Последний не предназначен для промышленной эксплуатации. [Документация PHP](https://www.php.net/manual/en/features.commandline.webserver.php).

Архив `windows-agent-all-in-one.zip` содержит агент, документацию, Windows PHP и установщик Visual C++ Runtime. Архив исходников `windows-agent.zip` содержит код, документацию и `vendor`, без Windows PHP. Открытая сборка с закреплёнными официальными компонентами описана в [docs/BUILD.md](docs/BUILD.md). Для автоматической установки в Git опубликованы `dist/windows-agent.zip` и его SHA-256; Windows PHP и VC++ скачиваются отдельно. После установки на Windows можно сформировать переносимый дистрибутив с фактически установленным PHP: см. раздел ниже.

1. Разместить PHP в `C:\Program Files\PHP`, каталог этого агента — в `C:\2fa\agent`.
2. В подготовленном архиве `windows-agent.zip` зависимости уже включены в `vendor`. Для установки из исходников без `vendor` выполнить из каталога агента:

   ```powershell
   composer install --no-dev --prefer-dist --no-interaction
   ```

3. Создать `C:\2fa\agent\config.json` из `config.dosifey.example.json` или `config.pimen.example.json`. Для Dosifey заданы `agentId: dosifey`, `domainController: dosifey.elemer.org`; для Pimen — `pimen` и `pimen.elemer.org`. Задать в `allowedIPs` постоянный исходящий IP мобильного сервера, который видит агент. Проверить `logDirectory: C:\2fa\logs`, `port: 8443`, пути TLS и PowerShell. Поле `apiSecretHex` оставить с заглушкой из примера: ключ создаст установщик. `bindAddress` задаёт адрес HTTPS API; доступ к нему ограничивают приложение и Firewall. Административная CLI использует локальный именованный канал Windows и от HTTPS-адреса не зависит.
4. Выбрать учётную запись запуска. Простой вариант — `SYSTEM`; на DC это высокопривилегированная учётная запись. Для эксплуатации предпочтительно заранее подготовить gMSA с правом чтения необходимых объектов/членства и записи `userWorkstations` только у целевых пользователей. Создание группы выполняет администратор отдельно.

При новой установке на каждом DC установщик сначала защищает права доступа, затем создаёт отдельный случайный HMAC-ключ из 32 байт и сохраняет его как 64 hex-символа в `config.json` → `apiSecretHex`. Значение ключа не выводится и не записывается в журналы. Заранее заполненный ключ при новой установке заменяется.

Перед установкой выпустите сертификат для текущего DC по разделу «Сертификаты HTTPS на десять лет» ниже. Установщик запускается из повышенной PowerShell-консоли:

```powershell
& 'C:\2fa\agent\deploy\Install-Agent.ps1' `
    -PhpPath 'C:\Program Files\PHP\php.exe'
```

После успешной установки администратор переносит `apiSecretHex` из защищённого файла в настройки **этого агента** на мобильном портале. Показать только нужное значение в повышенной консоли:

```powershell
(Get-Content -LiteralPath 'C:\2fa\agent\config.json' -Raw | ConvertFrom-Json).apiSecretHex
```

Портал автоматически не настраивается. Повторный запуск установщика при существующей задаче отказывает без смены ключа. После удаления и новой установки будет создан другой ключ — его нужно заново перенести на портал. Отдельного административного API-ключа нет; действующий `config.json` в дистрибутив не включается.

Установщик проверяет пути, защищает ACL корня `C:\2fa`, кода/конфигурации, журналов/документации и **всего выделенного каталога PHP** (включая `php.ini` и DLL). Удаляет наследуемые широкие разрешения, оставляет Administrators, Domain Admins по SID и SYSTEM; при отдельной gMSA ей выдаются чтение/запуск кода и запись журналов. На DC для администрирования используется встроенная группа Administrators; обычной отдельной локальной базы учётных записей нет. Установщик копирует `docs\instruction.txt` и `docs\api.txt` в `C:\2fa\docs`, добавляет правило Firewall для указанных IP/порта/`php.exe` и регистрирует задачи запуска и обслуживания журналов. PHP нужно размещать в собственном каталоге, не смешивая его с другими приложениями. Время работы задачи не ограничено тремя сутками, параллельные экземпляры этой задачи запрещены. После аварийного завершения предусмотрено до 999 перезапусков с интервалом минута. Это перезапуск того же агента, а не резервный механизм отзыва.

Установщик **не создаёт группу и не меняет пользователей**; без `-Start` процесс сразу не запускается. Для gMSA добавить `-ServiceAccount 'DOMAIN\mfa-agent$'`; учётная запись должна быть заранее установлена и доступна на данном DC. Установщик не ослабляет Execution Policy и не устанавливает исключения антивируса. Если политика требует подписанных PowerShell-скриптов, подпишите их доверенным сертификатом организации.

## Сертификаты HTTPS на десять лет

API агентов слушает `https://dosifey.elemer.org:8443` и `https://pimen.elemer.org:8443`; разрешены TLS 1.2 и TLS 1.3 при его поддержке PHP/OpenSSL. Веб-панель мобильной авторизации эта настройка не меняет. Агент не открывает HTTP-порт и не делает перенаправлений. Порт 8443 должен быть свободен: при существующем слушателе установщик отказывает до изменений и не останавливает другие службы.

В `config.json` задаются:

```json
{
  "port": 8443,
  "tlsCertificateFile": "C:\\2fa\\agent\\tls\\agent.crt.pem",
  "tlsPrivateKeyFile": "C:\\2fa\\agent\\tls\\agent.key.pem"
}
```

В используемом PHP включите `openssl`: в его `php.ini` задайте `extension_dir` как абсолютный путь к каталогу `ext` этой же сборки и `extension=openssl`. DLL OpenSSL должны быть доступны процессу PHP; не смешивайте библиотеки разных сборок. Проверка:

```powershell
& 'C:\Program Files\PHP\php.exe' --ri openssl
```

Подробности среды Windows приведены в [документации PHP OpenSSL](https://www.php.net/manual/en/openssl.installation.php).

Используется готовый шаблон **`WebServer10y`**, опубликованный на Enterprise CA `dosifey.elemer.org` по [внутренней инструкции AD CS](https://wiki.elemer.org/doku.php?id=oit:admins:iis_cert_ad_cs). Шаблон и десятилетний лимит выпуска CA уже настроены. Повторно создавать шаблон или менять общую политику CA не требуется. Скрипт проверяет публикацию шаблона, выдаваемый сертификат и его фактический срок.

Для диагностики выпуска или уточнения полного имени CA на Dosifey можно прочитать текущие значения:

```powershell
certutil -getconfig
certutil -getreg CA\ValidityPeriod
certutil -getreg CA\ValidityPeriodUnits
certutil -CAInfo cert
```

`-getconfig` показывает строку вида `dosifey.elemer.org\<имя CA>`; это имя самого CA, его нельзя заменять именем сервера. Сохраните точное значение для `-CAConfig`, если автоматическое обнаружение неоднозначно. `-CAInfo cert` позволяет проверить даты действующего сертификата CA. [Команды certutil](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/certutil).

Фактический срок ограничен шаблоном, политикой CA и оставшимся сроком сертификата CA. Если CA выдаёт менее десяти лет, скрипт прекращает выпуск; причину нужно разобрать с администратором существующего CA. Короткий остаток срока сертификата CA нельзя исправить параметром запроса. См. [ограничения срока Microsoft](https://learn.microsoft.com/en-us/troubleshoot/windows-server/certificates-and-public-key-infrastructure-pki/change-certificates-expiration-date).

Затем выполните запрос **отдельно на каждом DC** в повышенной PowerShell-консоли до `Install-Agent.ps1`:

```powershell
# На dosifey.elemer.org — сертификат с SAN dosifey.elemer.org.
& 'C:\2fa\agent\deploy\Request-AgentCertificate.ps1' `
    -PhpPath 'C:\Program Files\PHP\php.exe' `
    -CAHost 'dosifey.elemer.org' -Template 'WebServer10y'
```

```powershell
# На pimen.elemer.org — сертификат с SAN pimen.elemer.org.
& 'C:\2fa\agent\deploy\Request-AgentCertificate.ps1' `
    -PhpPath 'C:\Program Files\PHP\php.exe' `
    -CAHost 'dosifey.elemer.org' -Template 'WebServer10y'
```

FQDN определяется по локальному DC. Для явного выбора CA добавьте `-CAConfig 'dosifey.elemer.org\<точное имя CA>'`. Если заявка ожидает одобрения, администратор CA одобряет её, после чего повторите команду на исходном DC с `-RequestId <номер заявки>`.

Скрипт защищает папку TLS до создания ключа, проверяет соответствие ключа, SAN, назначение и цепочку сертификата, а также фактический срок. Срок берётся из атрибута pKIExpirationPeriod существующего шаблона WebServer10y: для десятилетнего шаблона ожидается интервал 3650–3653 дня. Если CA сократил этот интервал более чем на сутки, рабочие PEM-файлы не публикуются, выводятся фактические даты. Скрипт не меняет шаблон и настройки CA. После успеха дополнительно проверьте сертификат:

```powershell
certutil -dump 'C:\2fa\agent\tls\agent.crt.pem'
```

В `tls` находятся `agent.crt.pem` с сертификатом сервера и промежуточной цепочкой, `agent.key.pem` с закрытым ключом и публичный `ca-chain.pem`. Серверу мобильной авторизации передайте публичную цепочку для настройки доверия его TLS-клиента. Клиент обязан проверять цепочку, срок и имя соответствующего DC; отключать проверку сертификатов нельзя. Закрытый ключ остаётся на своём DC. Фактические даты выдачи фиксируются при выпуске; здесь сертификаты на реальном CA не выпускались.

## Полный дистрибутив для другого DC

Установщик создаёт защищённую папку `C:\2fa\distrib` и формирует `windows-agent-full.zip` с SHA-256. В него включаются исходники агента, `vendor`, установочные скрипты, шаблоны конфигурации, документация и PHP из выбранного `-PhpPath`. Для переносимого PHP создаётся новый `php.ini` из `php.ini-production`; рабочий `php.ini`, реальные `config.json`/API-секреты, TLS-сертификаты, закрытые ключи и журналы в пакет не входят. Каждый DC получает собственную пару ключа и сертификата. Папка дистрибутива доступна администраторам и SYSTEM.

Внутри ZIP расположены `agent/`, `php/`, `docs/`. На другом Windows Server 2022 с ролью контроллера домена:

1. Установить/проверить компоненты ОС: PowerShell 5.1, модуль ActiveDirectory и требуемый для PHP Microsoft Visual C++ Runtime. Они не входят в ZIP.
2. Перенести `windows-agent-full.zip` и файл SHA-256, проверить контрольную сумму и распаковать в `C:\2fa`.
3. Создать **новый** `C:\2fa\agent\config.json` из подходящего шаблона. Указать уникальный `agentId`, FQDN нового локального DC и постоянный исходящий IP мобильного сервера в `allowedIPs`; `apiSecretHex` оставить с заглушкой. Новый ключ создаст установщик на этом DC. Рабочий конфигурационный файл исходного агента не копировать. Включить `openssl` в переносимом PHP и выпустить отдельный сертификат для нового DC до запуска установщика.
4. Запустить повышенную PowerShell-консоль:

   ```powershell
   & 'C:\2fa\agent\deploy\Request-AgentCertificate.ps1' -PhpPath 'C:\2fa\php\php.exe' -Template 'WebServer10y'
   & 'C:\2fa\agent\deploy\Install-Agent.ps1' -PhpPath 'C:\2fa\php\php.exe'
   Start-ScheduledTask -TaskName TwoFactorAgent
   & 'C:\2fa\php\php.exe' 'C:\2fa\agent\bin\agentctl.php' --config 'C:\2fa\agent\config.json' status
   ```

5. После успешной установки перенести созданный `apiSecretHex` в настройки нового агента на мобильном портале.

После обновления программы полный дистрибутив можно пересобрать явно, указав фактически установленный PHP:

```powershell
& 'C:\2fa\agent\deploy\New-Distribution.ps1' `
    -CodePath 'C:\2fa\agent' `
    -PhpPath 'C:\Program Files\PHP\php.exe' `
    -DestinationPath 'C:\2fa\distrib'
```

Полный первоначальный комплект с официальным Windows PHP собран в Linux; переносимый комплект с фактически установленным PHP создаётся на Windows. Наличие архивов не означает, что файлы уже размещены на контроллерах.

## Первый запуск

Запустите процесс и проверьте его состояние:

```powershell
Start-ScheduledTask -TaskName TwoFactorAgent
& 'C:\Program Files\PHP\php.exe' 'C:\2fa\agent\bin\agentctl.php' `
    --config 'C:\2fa\agent\config.json' status
```

Агент при запуске проверяет доступность своего DC и конфигурацию. Если группы `2fabypass` ещё нет, HTTP-статус и локальные административные команды доступны, но `ready` равен `false` и выдачи отвергаются. Создайте группу командой `ensure-bypass --apply` ниже либо заранее штатными средствами AD. После успешной проверки агент становится готовым. Создание группы не выполняется при разрешении входа или включении таймера.

Группу создавайте **один раз на одном DC**, затем дождитесь её репликации и проверьте готовность второго. Не запускайте параллельное создание одноимённой группы на двух контроллерах. Применяемые к служебной учётной записи права на создание группы не требуются после предварительного создания администратором.

## Административные команды

Команды выполняются **только локально из повышенной консоли на соответствующем DC**. Агент должен быть запущен: CLI передаёт ему команды через именованный канал Windows, доступный администраторам и SYSTEM; сетевые подключения к каналу запрещены. Агент выполняет команды в общей очереди с выдачами и таймерами. HTTPS API содержит только выдачу, отзыв и статус; массовых и административных HTTP-маршрутов нет.

По умолчанию массовые операции показывают предварительный результат и не меняют AD:

```powershell
$agentPhp = 'C:\Program Files\PHP\php.exe'
$agentCli = 'C:\2fa\agent\bin\agentctl.php'
$agentConfigPath = 'C:\2fa\agent\config.json'
& $agentPhp $agentCli --config $agentConfigPath enable
& $agentPhp $agentCli --config $agentConfigPath enable --apply
& $agentPhp $agentCli --config $agentConfigPath disable
& $agentPhp $agentCli --config $agentConfigPath disable --apply
& $agentPhp $agentCli --config $agentConfigPath ensure-bypass --apply
```

Группу можно создать заранее штатными средствами AD. Массовые команды обходят весь домен, включая отключённые учётные записи, с обязательными исключениями. Обработка идёт ограниченными пакетами по десять пользователей с общим итоговым отчётом. Служебные пользовательские учётные записи нужно заранее добавить непосредственно в `2fabypass`. Отчёт содержит счётчики и ограниченное число ошибок; частичный результат не означает успешную обработку всего домена.

При применении выключения агент **сначала** прекращает выдачи и отменяет местные таймеры, затем очищает AD. Если очистка завершилась частично или с ошибкой, режим остаётся выключенным, а оставшиеся значения AD требуют повторного `disable --apply` после устранения причины. Включение переводит экземпляр в активный режим только после успешной массовой обработки; предварительный просмотр режим не меняет.

Записи AD и очистка по таймеру выполняются последовательно. Длительная текущая операция, в том числе пакет массовой обработки, может задержать отзыв до завершения операции или её таймаута. При ошибках AD очистка повторяется. Строгое удаление ровно на 300-й секунде не гарантируется; задержки AD, очередь и репликация дополнительно влияют на фактический момент запрета входа.

Во время массового обхода `status` доступен и показывает `bulk_running: true`; новые выдачи/отзывы через HTTPS получают 409, другая локальная массовая команда отклоняется. CLI ждёт итог массовой команды до `adminTimeoutSeconds` (по умолчанию 3600 секунд). Это отдельный клиентский предел: `processTimeoutSeconds` ограничивает каждый процесс PowerShell/пакет. Закрытие консоли или истечение времени ожидания CLI не отменяет уже принятую команду — сначала проверьте `status`. Частичный результат или неготовность после создания группы завершают CLI ненулевым кодом.

Массовое выключение — отдельная локальная административная процедура. Для полного выключения выполните `disable --apply` локально на каждом DC: это отключит выдачи в обоих экземплярах и отменит их местные таймеры, если команды успели обрабатывать оба. Для длительного выключения задайте `startEnabled: false` на обоих узлах, чтобы режим сохранялся после перезапуска. Обычные API-команды по-прежнему идут только на Dosifey, а при его недоступности — на Pimen.

Перед плановым обновлением или удалением можно дождаться завершения местных разрешений; иначе остановка потеряет их таймеры. `deploy\Uninstall-Agent.ps1` останавливает и удаляет задачи агента/ротации и правило Firewall. Код, конфигурация, журналы, документация, группа и атрибуты AD сохраняются; остановка сама по себе не отзывает разрешения.

## Журналы и ротация

События записываются в `C:\2fa\logs\agent-YYYY-MM-DD.jsonl`; время событий и дата файла — UTC. В журнал входят результаты операций и ошибки без ключей, подписей, полных HTTP-тел и исходных исключений AD. Это журнал для администратора: таймеры и режим из него не восстанавливаются.

Перед запуском агент проверяет возможность записи в папку журналов; при ошибке запуска не будет. Если запись перестала работать позже, очистка разрешений продолжается, а `/v1/status` показывает `logging_error: log_write_failed` и число потерянных событий `dropped_log_records`. Исправьте права/свободное место и проверьте восстановление записи.

`TwoFactorAgent-LogMaintenance` запускается при загрузке и ежедневно в 03:15 по времени сервера. Завершённые месяцы упаковываются в `C:\2fa\logs\archive\agent-YYYY-MM.zip`; текущий месяц не архивируется. Исходные файлы удаляются только после успешного закрытия и проверки ZIP. При ошибке сохраняются исходники и предыдущий исправный архив.

Хранение — три календарных года. Срок определяется периодом в имени файла, а не временем пересоздания архива. Старые дневные файлы удаляются по своей дате; месячный ZIP — когда весь его месяц старше границы хранения. Поэтому месяц, содержащий ещё актуальные дни, сохраняется целиком до достижения границы. Посторонние файлы обслуживание не удаляет. При остановленном сервере ротация/удаление продолжаются после запуска задачи.

```powershell
Get-ScheduledTaskInfo -TaskName TwoFactorAgent-LogMaintenance
Start-ScheduledTask -TaskName TwoFactorAgent-LogMaintenance
```

## Сетевые и процессные ограничения

По умолчанию `maxConnections: 100` ограничивает все соединения до TLS; `requestReceiveTimeoutSeconds: 5` — получение TLS, заголовков и полного тела. Ответ закрывает соединение. Команда API ждёт очереди не больше `queueWaitTimeoutSeconds: 2` с проверкой также на секундном такте. Истёкший запрос не запускает запись AD; текущая операция продолжает работать.

`processTimeoutSeconds: 30` ограничивает один процесс PowerShell (допустимо 1–60 секунд). Поиск и запись используют отдельные процессы, поэтому это не общий срок запроса. Таймаут отправителя не отменяет уже начатую запись. Измерить фактическую задержку на Windows перед выбором сетевого таймаута портала.
