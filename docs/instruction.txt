====== Агенты второго фактора: памятка администратора ======

Сервер мобильной авторизации начинает новую выдачу с первого настроенного агента и при неудаче переходит к следующему. Возможные получатели сохраняются до отправки; продление и отзыв закреплены за ними. После неизвестного результата очистка подтверждается у всех возможных получателей. Агенты работают независимо и изменяют AD на своём контроллере; репликацию выполняет AD.

===== Размещение =====

^ Назначение ^ Путь / значение ^
| Программа | ''C:\2fa\agent'' |
| Настройки | ''C:\2fa\agent\config.json'' |
| TLS-сертификат | ''C:\2fa\agent\tls\agent.crt.pem'' |
| Закрытый ключ TLS | ''C:\2fa\agent\tls\agent.key.pem'' |
| Журналы | ''C:\2fa\logs'' |
| Архивы журналов | ''C:\2fa\logs\archive'' |
| Эта инструкция | ''C:\2fa\docs\instruction.txt'' |
| Описание API | ''C:\2fa\docs\api.txt'' |
| Полный дистрибутив для другого DC | ''C:\2fa\distrib\windows-agent-full.zip'' |
| Задача запуска | ''TwoFactorAgent'' |
| Задача ротации | ''TwoFactorAgent-LogMaintenance'' |

В настройках ''agentId'' / ''domainController'': на первом сервере ''dosifey'' / ''dosifey.elemer.org'', на втором — ''pimen'' / ''pimen.elemer.org''. В ''allowedIPs'' указывается постоянный исходящий IP мобильного сервера, который видит агент. HTTPS-порт по умолчанию — ''8443'': ''https://dosifey.elemer.org:8443'' и ''https://pimen.elemer.org:8443''. Открытого HTTP и перенаправлений нет. HTTPS применяется к API агентов; веб-панель мобильной авторизации не меняется. Установщик создаёт отдельный API-секрет на каждом DC; после установки администратор переносит ''apiSecretHex'' в настройки этого агента на мобильном портале.

===== Как работает доступ =====

  * Разрешение добавляет ПК к списку «Вход на…» пользователя на настроенный срок (по умолчанию пять минут). Новое подтверждение той же пары продлевает срок; повтор доставки одной команды — нет.
  * При истечении любого разрешения пользователя весь список ПК заменяется заглушкой ''2FA-BLOCK''. Остальные местные таймеры этого пользователя отменяются.
  * Досрочный отзыв удаляет только указанный ПК и добавляет заглушку, если её нет.
  * Отдельный режим техподдержки снимает ограничение по всем рабочим станциям на настроенный срок, по умолчанию 60 секунд, в пределах существующих прав Windows. Затем устанавливается только заглушка. Контракт и ограничения при отказах: ''C:\2fa\agent\docs\support-api.md''. Capability ''support_all_v1'' обязательна; обычные и support-разрешения одного пользователя не смешиваются.
  * Открытые сеансы Windows/RDP продолжают работать. Агент не выполняет выход пользователя.
  * Прямые участники ''2fabypass'' не изменяются вообще; вложенное членство для этой группы не учитывается. Встроенный Administrator, Domain Admins, Enterprise Admins и Administrators исключены из всех операций.

Реального компьютера ''2FA-BLOCK'' в домене быть не должно. Добавление заглушки сохраняет ранее разрешённые ПК; пустой список означает отсутствие ограничений по рабочим станциям.

===== Установка с автоматической загрузкой =====

Новая установка на каждом DC: скачать [[https://raw.githubusercontent.com/skylevels/2fa-winagent/main/deploy/Install-AgentOnline.ps1|Install-AgentOnline.ps1]] и запустить в 64-битной Windows PowerShell **от имени администратора**:

<code powershell>
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$installerPath = Join-Path $env:TEMP 'Install-AgentOnline.ps1'
Invoke-WebRequest -UseBasicParsing -TimeoutSec 120 -Uri 'https://raw.githubusercontent.com/skylevels/2fa-winagent/main/deploy/Install-AgentOnline.ps1' -OutFile $installerPath
& $installerPath -CAHost 'dosifey.elemer.org'
</code>

Указать фактический IP мобильного сервера по запросу скрипта либо передать ''-AllowedIP '192.0.2.10''' со своим адресом. При необходимости добавить ''-CAConfig 'dosifey.elemer.org\<имя-CA>'''; шаблон — ''WebServer10y''.

Скрипт скачает исходники с зависимостями, официальный PHP и VC++ Runtime, проверит SHA-256 и подпись Microsoft, настроит PHP/OpenSSL, получит сертификат, установит и запустит агент на HTTPS:8443. Требуются интернет, модуль ActiveDirectory и настроенный CA/шаблон. Права папок ограничиваются до записи. Существующая установка не перезаписывается. Если VC++ потребует перезагрузку — перезагрузить и повторить скрипт: агент ещё не будет размещён или запущен.

Если запрос сертификата ожидает согласования, после одобрения продолжить ''Request-AgentCertificate.ps1'' с ''-RequestId <ID>'' и ''-PhpPath 'C:\2fa\php\php.exe''', затем ''Install-Agent.ps1 -PhpPath 'C:\2fa\php\php.exe'''. Файлы и настройки при сбое сохраняются. Зарегистрированные задачи повторной установкой не заменяются.

После установки перенести HMAC в настройки соответствующего агента на портале и проверить группу ''2fabypass'' по разделу команд администратора. Массовое включение скрипт самостоятельно не выполняет. Ниже сохранён порядок установки из готового комплекта без интернет-загрузки.

===== Установка и доступ к файлам =====

Код распаковать в ''C:\2fa\agent'', подготовить ''config.json'' из ''config.dosifey.example.json'' или ''config.pimen.example.json'', указать постоянный исходящий IP мобильного сервера в ''allowedIPs''. Поле ''apiSecretHex'' оставить с заглушкой из примера — его заполнит установщик. Перед установкой включить в PHP расширение ''openssl'' и выпустить сертификат по разделу ниже. Установку выполнять из PowerShell **от имени администратора**:

<code powershell>
& 'C:\2fa\agent\deploy\Install-Agent.ps1' -PhpPath 'C:\Program Files\PHP\php.exe'
Start-ScheduledTask -TaskName TwoFactorAgent
</code>

После защиты прав доступа установщик создаёт случайный HMAC-ключ и сохраняет его в ''config.json'' → ''apiSecretHex''; сам ключ не выводит и не журналирует. После успешной установки посмотреть значение в повышенной консоли и перенести в настройки этого агента на портале:
<code powershell>
(Get-Content -LiteralPath 'C:\2fa\agent\config.json' -Raw | ConvertFrom-Json).apiSecretHex
</code>
Портал автоматически не настраивается. При существующей задаче повторный запуск установщика отказывает без смены ключа; удаление и новая установка создают новый ключ, который нужно заново перенести на портал.

Установщик создаёт папки журналов/документации и копирует два TXT-файла в ''C:\2fa\docs''. Наследование широких прав удаляется: код, настройки и документация доступны Administrators, Domain Admins и SYSTEM. При запуске под отдельной gMSA ей предоставляются технические права чтения/запуска; запись — в журналы. Обычный доменный пользователь читать эти файлы не должен. На DC для администраторов используется встроенная группа Administrators; отдельной обычной локальной базы пользователей, как на рядовом сервере, нет.

===== Проверка порта перед установкой =====

API агентов использует HTTPS:8443. С Mac проверить доступность каждого контроллера:

<code bash>
nc -vz -G 3 dosifey.elemer.org 8443
nc -vz -G 3 pimen.elemer.org 8443
</code>

''succeeded'' означает доступный слушатель; ''Connection refused'' — нет доступного слушателя либо соединение активно отклонено. Таймаут может означать Firewall или сетевую недоступность. У агента разрешён только IP мобильного сервера, поэтому проверка с Mac не доказывает отсутствие службы. Точную занятость проверить локально на Windows из повышенной PowerShell-консоли перед установкой:

<code powershell>
Get-NetTCPConnection -State Listen -LocalPort 8443 -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, OwningProcess
</code>

Нет вывода — активного TCP-слушателя на 8443 нет. Установщик также проверяет порт перед изменениями. После запуска в настройках портала указать ''https://<agent-host>:8443''. Сертификат продолжает проверяться по DNS-имени; смена порта не требует его перевыпуска.

===== HTTPS и сертификаты на десять лет =====

В ''config.json'': ''port: 8443'', ''tlsCertificateFile: C:\2fa\agent\tls\agent.crt.pem'', ''tlsPrivateKeyFile: C:\2fa\agent\tls\agent.key.pem''. В PHP нужен ''openssl''; проверить:
<code powershell>
& 'C:\Program Files\PHP\php.exe' --ri openssl
</code>

Используется готовый шаблон **''WebServer10y''**, опубликованный на Enterprise CA ''dosifey.elemer.org'' по [[https://wiki.elemer.org/doku.php?id=oit:admins:iis_cert_ad_cs|внутренней инструкции AD CS]]. Шаблон и десятилетний лимит CA уже настроены; повторять настройку не требуется. Скрипт находит CA на Dosifey автоматически и проверяет фактически выданный срок.

В повышенной консоли **на Dosifey, затем отдельно на Pimen** выполнить до установщика:
<code powershell>
& 'C:\2fa\agent\deploy\Request-AgentCertificate.ps1' `
    -PhpPath 'C:\Program Files\PHP\php.exe' `
    -CAHost 'dosifey.elemer.org' -Template 'WebServer10y'
certutil -dump 'C:\2fa\agent\tls\agent.crt.pem'
</code>
Каждый DC получает собственный сертификат с SAN своего FQDN. Если обнаружено несколько CA, добавить ''-CAConfig 'dosifey.elemer.org\<точное имя CA>''' из ''certutil -getconfig'', выполненного на Dosifey. При ожидании одобрения — одобрить заявку на CA и повторить команду с ''-RequestId <номер>''. Скрипт читает срок существующего шаблона WebServer10y из AD (для десяти лет — 3650–3653 дня) и сравнивает с фактическими датами сертификата. Если CA сократил срок более чем на сутки, рабочие PEM-файлы не публикуются. Настройки CA и шаблона не изменяются.

Публичный ''C:\2fa\agent\tls\ca-chain.pem'' передать мобильному серверу для настройки доверия его TLS-клиента. Проверка цепочки, срока и DNS-имени обязательна. Закрытый ключ остаётся на своём DC; в переносимый дистрибутив TLS-файлы не входят.

===== Дистрибутив для другого контроллера =====

Исходники агента опубликованы в [[https://github.com/skylevels/2fa-winagent|skylevels/2fa-winagent]]. При установке из клона репозитория сначала выполнить composer install --no-dev --prefer-dist --no-interaction в папке агента. Автоматический установщик скачивает подготовленные зависимости; готовый полный комплект также содержит официальный PHP.


При установке в защищённой папке ''C:\2fa\distrib'' создаются ''windows-agent-full.zip'' и контрольная сумма SHA-256. В архиве — агент, библиотеки, установленный PHP, шаблоны настроек и документация; рабочих секретов, ''config.json'', TLS-сертификатов, закрытых ключей и журналов нет. Перенести ZIP и его SHA-256 на новый DC, проверить сумму, распаковать в ''C:\2fa'' (папки ''agent'', ''php'', ''docs''). Подготовить новый ''agent\config.json'' из шаблона: заменить agentId, domainController и постоянный исходящий IP в ''allowedIPs'', оставить заглушку в ''apiSecretHex''. Установщик на новом DC создаст собственный ключ; после успешной установки перенести его в настройки этого агента на портале. Включить ''openssl'' в переносимом PHP и выпустить для нового DC собственный сертификат:
<code powershell>
& 'C:\2fa\agent\deploy\Request-AgentCertificate.ps1' -PhpPath 'C:\2fa\php\php.exe' -Template 'WebServer10y'
& 'C:\2fa\agent\deploy\Install-Agent.ps1' -PhpPath 'C:\2fa\php\php.exe'
Start-ScheduledTask -TaskName TwoFactorAgent
</code>
На новом сервере нужны Windows Server 2022 с ролью DC, модуль ActiveDirectory и Microsoft Visual C++ Runtime: эти компоненты ОС в архив не входят. Для последующих команд использовать фактический PHP, здесь — ''C:\2fa\php\php.exe''. Обновить полный архив после изменения кода можно так (указать установленный PHP):
<code powershell>
& 'C:\2fa\agent\deploy\New-Distribution.ps1' -CodePath 'C:\2fa\agent' -PhpPath 'C:\Program Files\PHP\php.exe' -DestinationPath 'C:\2fa\distrib'
</code>
Полный ZIP собирается установщиком на Windows из установленного PHP. Исходный ''windows-agent.zip'' с кодом и библиотеками PHP-интерпретатор не содержит.

===== Команды администратора =====

Команды выполнять **только локально на нужном DC из повышенной PowerShell-консоли**. Агент должен быть запущен. CLI связывается с ним через именованный канал Windows: доступ разрешён администраторам и SYSTEM, подключения к каналу по сети запрещены. Массовые операции и создание группы через HTTPS API недоступны. Сначала задать пути:

<code powershell>
$php = 'C:\Program Files\PHP\php.exe'
$cli = 'C:\2fa\agent\bin\agentctl.php'
$cfg = 'C:\2fa\agent\config.json'
& $php $cli --config $cfg status
</code>

''ready: true'' — каталог готов; ''enabled: true'' — выдача разрешений включена; ''pending_cleanup'' — неподтверждённая очистка; ''bulk_running'' — массовая операция. Ошибку или частичный результат нельзя считать выполнением команды.

<code powershell>
# Создать 2fabypass один раз на одном DC, затем дождаться репликации.
& $php $cli --config $cfg ensure-bypass --apply
# Предварительный просмотр / включение для всего домена.
& $php $cli --config $cfg enable
& $php $cli --config $cfg enable --apply
# Предварительный просмотр / выключение для всего домена.
& $php $cli --config $cfg disable
& $php $cli --config $cfg disable --apply
</code>

Включение только добавляет заглушку. Выключение сначала прекращает новые выдачи и отменяет местные таймеры, затем полностью очищает списки обычных пользователей. **Для полного выключения выполнить команду локально на каждом DC:** отключатся оба экземпляра и отменятся их местные таймеры, если команды обрабатывали оба. Это отдельная административная процедура; обычные API-команды обоим не дублируются. При частичной ошибке режим остаётся выключенным: устранить причину и повторить команду. Служебные учётные записи заранее добавить напрямую в ''2fabypass''.

Без ''--apply'' команды ''enable'' и ''disable'' выполняют только предварительный просмотр. Обход идёт пакетами, результат содержит число найденных, изменённых, исключённых пользователей и ошибок. CLI ждёт результат до ''adminTimeoutSeconds'' (по умолчанию 3600 секунд); закрытие консоли или таймаут не отменяет уже принятую команду. Перед повтором проверить ''status''.

===== Ограничения ожидания и нагрузки =====

В ''config.json'': ''requestReceiveTimeoutSeconds: 5'' — получение TLS и полного HTTP-запроса; ''maxConnections: 100'' — открытые соединения; ''queueWaitTimeoutSeconds: 2'' — ожидание API-команды до начала обработки. Просроченная команда не меняет AD; очередь дополнительно проверяется раз в секунду. ''processTimeoutSeconds: 30'' ограничивает каждый PowerShell-процесс, допустимо 1–60 секунд. Несколько процессов внутри команды имеют отдельные сроки.

Таймаут портала не останавливает уже начатую запись AD. Проверка доступности ограничена 3 секундами, команда имеет отдельный конечный бюджет 130 секунд по умолчанию. Перед включением измерить выдачу и отзыв на обоих DC. Для крупных доменов отдельно проверить время массового обхода: каждый пакет повторно перечисляет пользователей домена.

Проверить синхронизацию времени, реальный вход/разблокировку/RDP и кэшированный вход без DC. Запись ''userWorkstations'' сама по себе не подтверждает защиту всех вариантов входа. Подробный отчёт — ''C:\2fa\docs\SECURITY-REVIEW.md'', оставшиеся испытания — ''WINDOWS-VALIDATION.md''.

===== Ручная настройка длительности =====

В ''C:\2fa\agent\config.json'' изменить значения существующих полей:

<code json>
"grantDurationSeconds": 300,
"supportDurationSeconds": 60,
</code>

  * ''grantDurationSeconds'' — обычный доступ: 30–600 секунд, по умолчанию 300 (5 минут).
  * ''supportDurationSeconds'' — техподдержка: 30–180 секунд, по умолчанию 60 (1 минута).

Только целые числа, одинаковые на всех участвующих агентах. Портал читает их из подписанного статуса; его таймер использует выбранное значение. Конфиг применяется при запуске процесса. После завершения текущих окон и подтверждённой очистки изменить файл на каждом DC и перезапустить задачу в повышенной PowerShell:

<code powershell>
Stop-ScheduledTask -TaskName TwoFactorAgent
Start-ScheduledTask -TaskName TwoFactorAgent
</code>

Перед остановкой проверить ''active_grants: 0'' и ''pending_cleanup: 0'': память таймеров после перезапуска не восстанавливается. Новые значения применяются к новым разрешениям после запуска.

===== Повторы ручного отзыва =====

Если ручной отзыв временно завершился ошибкой AD, портал может повторить тот же запрос исходному агенту. Агент сверяет тело, исходную учётную запись по GUID и последний номер команды; более новая команда запрещает выполнение старого отзыва. Ошибка не становится вечным отказом из-за кэша. Неудавшиеся выдачи автоматически повторно не исполняются.

По окончании настроенного срока агент сам запускает очистку по местному таймеру; портал не отправляет плановый HTTP-отзыв. Досрочный отзыв поступает только по кнопке. Локальное истечение портала не означает подтверждённую очистку AD.

===== Остановка и перезапуск =====

<code powershell>
Get-ScheduledTask -TaskName TwoFactorAgent
Stop-ScheduledTask -TaskName TwoFactorAgent
Start-ScheduledTask -TaskName TwoFactorAgent
</code>

**Остановка теряет таймеры, но не удаляет записанные разрешения AD.** Перед плановым обслуживанием можно дождаться окончания местных разрешений; иначе их таймеры будут потеряны. После старта режим берётся из ''startEnabled''; для длительного выключения установить ''false'' на обоих узлах. Журналы не используются для восстановления таймеров.

Когда Dosifey снова доступен, новые выдачи снова выбирают его первым. Продление и ручной отзыв закреплены за возможными получателями исходной выдачи. Передачи таймеров и сверки состояния между агентами нет. Для редких отказов допустимы потерянные таймеры и удаление новой выдачи старым таймером другого агента; автоматическая компенсация порталом не предусмотрена. Открытые Windows/RDP-сеансы продолжаются.

===== Журналы и ротация =====

Журнал за день: ''C:\2fa\logs\agent-YYYY-MM-DD.jsonl''. Время событий и имена дневных файлов — UTC. Записываются результаты операций и ошибки; секреты, подписи и полные тела HTTP-запросов не сохраняются. При невозможности записи ''status'' показывает ''logging_error'' и число потерянных записей ''dropped_log_records''; очистка доступов при этом продолжается.

Задача ''TwoFactorAgent-LogMaintenance'' запускается при загрузке сервера и ежедневно в **03:15 по времени сервера**. Каждый завершённый месяц упаковывается в ''archive\agent-YYYY-MM.zip''. Исходные файлы удаляются только после проверки архива. Текущий месяц остаётся в дневных файлах.

Срок хранения — **три календарных года**. Старые дневные файлы удаляются по дате в имени; месячный архив — когда весь его месяц старше границы хранения. Пересоздание архива не продлевает срок. При выключенном сервере обслуживание продолжится после следующего запуска.

<code powershell>
Get-ScheduledTaskInfo -TaskName TwoFactorAgent-LogMaintenance
Start-ScheduledTask -TaskName TwoFactorAgent-LogMaintenance
Get-ChildItem 'C:\2fa\logs'
# Подставить нужную дату UTC.
Get-Content 'C:\2fa\logs\agent-2026-11-05.jsonl' -Tail 50
</code>

При проблемах проверить ''status'', последние журналы, результат задачи ротации, доступность AD и репликацию. До ввода в эксплуатацию на Windows Server 2022 проверить права файлов и локального канала, работу CLI под PowerShell 5.1, новые входы, RDP и разблокировку на Windows 10/11; уже открытый сеанс должен сохраняться.
